# 保育士試験一問一答アプリ 仕様書

## 1. この仕様書について

この文書は、Reactで作成する「保育士試験一問一答アプリ」の初回版の仕様を定める。

本仕様は、次の資料を確認して作成した。

- `assets/question_data.js`（問題データ）
- `参考資料.html`（既存のHTML版。参照のみで、編集対象ではない）
- 本仕様書作成時に提示された基本仕様と対象外機能

Reactのコンポーネント構成、stateの持ち方、ファイル構成などの詳細な実装方法は、この仕様書では決定しない。ただし、学習対象をJavaScriptとReactに絞るため、アプリの実装にはJavaScriptとJSXを使用し、TypeScriptは使用しない。

本文では情報を次のように区別する。

- **確定仕様**: 提示された要件、または初回版として採用する動作
- **確認できた事実**: データやHTML版から実際に読み取れた内容
- **提案**: データからは決められないが、初回版の候補となる内容
- **確認事項**: 人間による判断が必要で、現時点では仕様を確定しない内容

## 2. アプリの目的

### 確定仕様

保育士試験の受験者が、科目とテーマを選び、選択式の問題を一問ずつ解いて知識を確認できる、シンプルなWebアプリを提供する。

また、このプロジェクトはReact初学者が学びながら開発することを目的とする。そのため初回版は、機能や画面を必要最小限にし、処理の流れを追いやすい構成とする。

## 3. 想定利用者

### 確定仕様

- 保育士試験の受験者
- 主な利用者は30〜50代の女性で、子どもが好きな社会人・主婦などを想定する
- 男性利用者も全体の10〜15%程度を想定する
- 短い時間でも、迷わず科目・テーマを選んで学習を進められることを重視する

## 4. 初回版の対象範囲

### 4.1 初回版で実装する機能

### 確定仕様

- 科目一覧の表示
- 科目ごとのテーマカラーを使った科目選択ボタンの表示
- 科目ごとのテーマ数・総問題数の表示

- 回答結果の `users_data` への反映
- 正しい選択肢と、誤答時に選んだ選択肢の表示
- 解説の表示
- データに並んだ順での次問題への移動
- 全問終了後の正解数・不正解数の表示

### 4.2 初回版では実装しない機能

### 確定仕様

- ログイン
- ユーザー登録

- 学習履歴の保存

- 問題のランダム出題
- 管理画面
- 外部API
- 高度なアニメーション

「問題のランダム出題」は行わず、問題は `questions` 配列の先頭から順に出題する。選択肢の並び替えについては、問題の出題順とは別の動作として「10. 一問一答の進行方法」に記載する。

## 5. 確認したデータ構造の概要

### 5.1 データファイルの構成

### 確認できた事実

`assets` フォルダ内で確認できたデータファイルは `question_data.js` の1ファイルである。

このファイルはJSONファイルではなく、JavaScriptのデータとして次の2つの変数を定義している。

- `subjects`: 科目、テーマ、問題を階層的に保持する配列
- `users_data`: 問題IDごとの回答状態とお気に入り状態を保持するオブジェクト

確認時点のデータ件数は次のとおりである。

| 種別 | 件数 |
| --- | ---: |
| 科目 | 9 |
| テーマ | 13 |
| 問題 | 134 |

| `theme_list` | 科目に属するテーマの配列 | テーマ一覧の取得に使用する |

データ内の科目とテーマ数は次のとおりである。

| 社会福祉 | 0 |

| 子どもの食と栄養 | 2 |
| 保育実習理論 | 2 |

### 5.3 テーマデータの項目

### 確認できた事実

| 項目名 | データの内容 | 初回版での扱い |
| --- | --- | --- |
| `theme` | テーマ名 | テーマ選択画面とテーマ紹介画面に表示する |
| `quantity` | テーマ内の問題数として保存された値 | 参考値として保持するが、表示や終了判定では `questions` の件数を正とする |
| `theme_comment` | テーマの紹介文 | テーマ紹介画面に表示する |
| `questions` | テーマに属する問題の配列 | 一問一答で先頭から順に使用する |

確認時点では、全テーマで `quantity` と `questions` 配列の実際の要素数が一致している。

### 5.4 問題データの項目

### 確認できた事実

| 項目名 | データの内容 | 確認できた値・利用方法 |
| --- | --- | --- |
| `tag` | 問題の分類用と思われる値 | 全134問が `0`。HTML版では使用していない |
| `q_type` | 問題種別 | `null` または `"正誤"`。HTML版では正誤問題の選択肢を並び替えない判定に使う |
| `pre_question` | 問題文の前に表示する短い案内 | 空文字または文字列。HTML版では問題番号の後に表示する |
| `question_id` | 問題を識別する文字列 | 全問題に存在する。`users_data` のキーにも使われる |
| `block_shuffle` | 選択肢の並び替えを止める指定 | `null` または `1`。HTML版では `null` 以外なら並び替えない |
| `question` | 問題文 | 全問題に存在する |
| `question_img` | 問題画像のファイル名 | 全問題が `null`。初回版では使用しない |
| `choices` | 選択肢の配列 | 全問題に存在し、選択肢数は2〜4個 |
| `answer` | 正解となる選択肢の位置 | `0`〜`3`の数値。0始まりで `choices` の位置を示す |
| `comment_1` | 回答後に表示する解説 | 127問に文字列があり、7問は `null` |
| `goro_img` | 語呂合わせ画像のファイル名 | 6問に `"たかるカビ都市"`、その他は `null`。初回版では使用しない |
| `comment_2` | 今後の機能で使用予定の項目 | 全問題が `null`。初回版では使用しないが、データから削除しない |
| `mitei` | 今後の機能で使用予定の項目 | 全問題が `null`。初回版では使用しないが、データから削除しない |

`tag`、`comment_2`、`mitei` は初回版では使用しないが、今後の実装で使用する予定があるため、データから削除しない。

画像関連項目の文字列は、特定の画像フォルダ内にあるファイルの名前を表す。画像を使用するときは値の末尾に `.jpg` を付けてファイルを指定する。ただし、初回版では画像機能を使用しない。

### 5.5 `users_data` の項目

### 確認できた事実

`users_data.question` の下に、`question_id` をキーとして次の項目がある。

| 項目名 | 確認できた初期値 | HTML版での扱い |
| --- | --- | --- |
| `solved` | 文字列の `"null"` | 回答後に `"correct"` または `"incorrect"` を入れ、テーマ画面の正解数表示に使う |
| `favorite` | `false` | HTML版では使用していない |

HTML版の更新内容はブラウザのメモリ上だけであり、再読み込み後も残る保存処理は確認できなかった。

### 確定仕様

初回版でも、回答した問題の `question_id` に対応する `users_data.question` の `solved` を、正解なら `"correct"`、不正解なら `"incorrect"` に更新する。この情報を、同じブラウザ表示中のテーマ別正解数と進捗表示に使用する。ブラウザを再読み込みした後まで保存する必要はない。`favorite` は初回版では使用しない。

## 6. 科目・テーマ・問題の関係と表示順

### 確定仕様

データは次の親子関係を持つ。

```text
subjects（科目一覧）
└─ 1つの科目
   └─ theme_list（その科目のテーマ一覧）
      └─ 1つのテーマ
         └─ questions（そのテーマの問題一覧）
```

- 1つの科目は0個以上のテーマを持つ
- 1つのテーマは問題の配列を持つ
- 科目は `subjects` 配列の順に表示する
- テーマは `theme_list` 配列の順に表示する
- 問題は `questions` 配列の順に、問1、問2、問3……として出題する
- 問題番号は現在の配列位置から表示し、`question_id` の文字列を画面上の問題番号として使用しない

### 確認できた事実

確認時点の `question_id` は各テーマ内で `..._001` から連番になっており、データの配列順もこの順番と一致している。ただし、出題順を指定する専用項目は存在しない。HTML版も配列の位置を使って順に出題している。

## 7. 画面構成

初回版は、次の5画面で構成する。

1. 科目選択画面
2. テーマ選択画面
3. テーマ紹介画面
4. 一問一答画面
5. 結果画面

「画面」は利用者から見た表示単位を表す。URLの分け方やReact上の実装方法は、この仕様書では決定しない。

## 8. 各画面の役割・表示内容・操作

### 8.1 科目選択画面

#### 役割

アプリ起動時に、学習する科目を選ぶ。

#### 表示内容

### 確定仕様

- アプリ名「保育士試験一問一答」
- `subjects` に含まれる科目の一覧
- 各科目の表示名には `subjects.name` を使用する
- 各科目のテーマ数
- 各科目に属する全テーマの `questions` の件数を合計した総問題数
- 各科目の `color` をテーマカラーとして使用した科目選択ボタン

#### 利用者の操作

### 確定仕様

- 科目を1つ選択すると、その科目のテーマ選択画面へ進む

### 8.2 テーマ選択画面

#### 役割

選択した科目に属するテーマから、学習するテーマを選ぶ。

#### 表示内容

### 確定仕様

- 選択した科目の `theme_list` に含まれるテーマ一覧
- 各テーマの `theme`
- 各テーマの `questions` の件数を使った全問題数
- `users_data.question.solved` が `"correct"` の問題を数えた現在の正解数
- 「現在の正解数 ÷ `questions` の件数」で表す進捗バー
- 科目選択画面へ戻る操作
- テーマが0件の場合は「まだコンテンツがありません。」

#### 利用者の操作

### 確定仕様

- テーマを1つ選択すると、そのテーマのテーマ紹介画面へ進む
- 戻る操作で科目選択画面へ戻る
- テーマが0件の場合、テーマを選ぶ操作はできない

正解数と進捗は現在のブラウザ表示中だけ保持する。再読み込み後は `users_data` の初期値に戻る。

### 8.3 テーマ紹介画面

#### 役割

選択したテーマの概要を読んでから、一問一答を開始する。

#### 表示内容

### 確定仕様

- 選択したテーマの `theme`
- 選択したテーマの `theme_comment`
- 「問題を解く」ボタン
- テーマ選択画面へ戻る操作

`theme_comment` 内の改行は、画面上でも段落や改行として読めるように表示する。

#### 利用者の操作

### 確定仕様

- 「問題を解く」ボタンで一問一答画面へ進み、問1から開始する
- 戻る操作でテーマ選択画面へ戻る

### 確認できた事実と初回版との差

HTML版の該当画面は「学習モード選択」という名称で、「テストモード」と「カンニングモード」の2つを表示する。今回提示された基本仕様では「問題を解く」ボタンを1つ表示すると指定されているため、初回版は正誤を判定する一問一答のみとし、モード選択は設けない。

### 8.4 一問一答画面

#### 役割

選択したテーマの問題を、一問ずつ順番に解く。

#### 回答前の表示内容

### 確定仕様

- 選択中の科目名
- 選択中のテーマ名
- 「問1」のような現在の問題番号
- `pre_question`。空文字の場合は、内容のない余分な表示を行わない
- `question`
- `choices` に含まれる選択肢
- テーマ選択画面へ戻る操作

#### 回答後の表示内容

### 確定仕様

- 「正解！」または「不正解」
- 正しい選択肢が分かる表示
- 不正解の場合は、利用者が選んだ誤った選択肢が分かる表示
- 「解説」の見出し
- `comment_1` の解説文
- 「次へ」ボタン
- テーマ選択画面へ戻る操作

#### 利用者の操作

### 確定仕様

- 回答前は、選択肢を1つ選んで回答する
- 1問につき回答できるのは1回とする
- 回答時に、正解なら該当問題の `users_data.question.solved` を `"correct"`、不正解なら `"incorrect"` に更新する
- 回答後は選択肢を変更できない
- 「次へ」で次の問題へ進む
- 最後の問題で「次へ」を押すと結果画面へ進む
- 戻る操作で、確認画面を挟まずテーマ選択画面へ戻る

一問一答の途中で戻った場合の再開位置は保存しない。もう一度同じテーマの「問題を解く」を選んだ場合は問1から始める。

### 8.5 結果画面

#### 役割

選択したテーマの全問題が終了したことと、今回の結果を知らせる。

#### 表示内容

### 確定仕様

- 「全問終了！」
- 今回の正解数
- 今回の不正解数
- 選択していた科目のテーマ選択画面へ戻る操作

#### 利用者の操作

### 確定仕様

- 戻る操作で、選択していた科目のテーマ選択画面へ戻る

結果は今回の一問一答中だけで使用し、ブラウザを再読み込みした後まで保存しない。

## 9. 画面遷移

### 確定仕様

```text
アプリ起動
  ↓
科目選択画面
  ├─ 科目を選ぶ → テーマ選択画面
  │                  ├─ テーマを選ぶ → テーマ紹介画面
  │                  │                  ├─ 問題を解く → 一問一答画面
  │                  │                  │                └─ 全問終了 → 結果画面
  │                  │                  │                              └─ 戻る → テーマ選択画面
  │                  │                  └─ 戻る → テーマ選択画面
  │                  └─ 戻る → 科目選択画面
  └─ テーマがない科目でもテーマ選択画面へ進み、案内文を表示する
```

一問一答画面の「戻る」は、HTML版に合わせて確認画面を挟まずテーマ選択画面へ戻る。ブラウザの戻るボタンを押した場合の動作やURL履歴の扱いは、実装方法に関係するためこの仕様書では決定しない。

## 10. 一問一答の進行方法

### 確定仕様

1. テーマ紹介画面で「問題を解く」を押す。
2. 選択したテーマの `questions[0]` を問1として表示する。
3. `choices` から1つを選ぶ。
4. 選んだ選択肢の元データ上の位置と `answer` を比較する。
5. 一致すれば今回の正解数を1増やし、該当問題の `users_data.question.solved` を `"correct"` にして、「正解！」と表示する。
6. 一致しなければ該当問題の `users_data.question.solved` を `"incorrect"` にして、「不正解」と表示する。
7. 正しい選択肢を示し、不正解の場合は選択した誤答も示す。
8. `comment_1` を解説として表示する。
9. 「次へ」を押すと、`questions` 配列の次の問題を表示する。
10. 最終問題の回答確認後に「次へ」を押すと、結果画面を表示する。
11. 結果画面に、今回の正解数と「`questions` の件数 - 正解数」で求めた不正解数を表示する。

問題数の表示、最終問題の判定、不正解数の計算では、`quantity` ではなく実際の `questions` の件数を正とする。

### 選択肢の表示順

### 確認できた事実

HTML版のテストモードは、次の条件で選択肢の表示順を変えている。

- `q_type` が `"正誤"` の問題: データの順番を維持する
- `block_shuffle` が `null` ではない問題: データの順番を維持する
- 上記以外: 選択肢をランダムに並び替える

並び替えても、正解判定には各選択肢が元々持っていた位置を使用している。

### 確定仕様

初回版も上記の条件を尊重する。ただし、ランダムになるのは選択肢の表示順だけであり、問題の出題順は変更しない。

## 11. データが存在しない場合の表示

### 確定仕様

| 状況 | 表示・動作 |
| --- | --- |
| 選択した科目の `theme_list` が空 | 「まだコンテンツがありません。」と表示する |
| `pre_question` が空文字 | 前置き文を表示せず、問題番号と問題文を表示する |
| `comment_1` が `null` | HTML版に合わせて「まだ解説はありません。」と表示する |
| `question_img` が `null` | 画像表示欄を設けない |
| `comment_2` が `null` | 追加解説欄を設けない |
| `mitei` が `null` | 対応する表示欄を設けない |

### 確定仕様

現在のデータには、`questions` が空のテーマ、`theme_comment` がないテーマ、`question` や `choices` がない問題は存在しない。初回版ではエラー処理を追加せず、これらの必須データは正しく存在するものとして扱う。

## 12. HTML版から読み取った全体仕様

### 確認できた事実

HTML版では、1ページ内の表示内容を切り替えて次の順に学習する。

1. 科目を選択する。
2. 選択した科目のテーマを選択する。テーマがなければ案内文を表示する。
3. テーマ紹介文を読み、「テストモード」または「カンニングモード」を選ぶ。
4. 問題番号、前置き、問題文、選択肢を表示する。
5. テストモードでは、選択肢を押すとその場で正誤、正解選択肢、解説を表示する。
6. カンニングモードでは、回答前から正解選択肢と解説を表示する。
7. 「次へ」で配列順に進み、全問終了後に正解数と不正解数を表示する。
8. 各段階から科目またはテーマの選択画面へ戻れる。

HTML版は科目ごとの色、科目のテーマ数・総問題数、テーマごとの全問題数・正解数・進捗バーも表示する。また、回答結果を `users_data` に反映するが、永続保存する処理はない。

初回版では、提示された基本仕様と最小構成を優先し、HTML版のうち一問一答に必要な流れだけを採用する。

## 13. アプリ全体の完了条件

## 14. データ構造から分かった注意点

### 確認できた事実

1. `answer` は選択肢の番号そのものではなく、0から始まる `choices` 配列上の位置である。画面上の1番目はデータ上の `0` に対応する。
2. 選択肢は2個、3個、4個の問題があるため、固定数を前提にできない。
3. `pre_question` には空文字が多いが、一部の問題には「○か×か。」などの文がある。
4. `q_type` が `"正誤"` の問題では、`choices` は `［"○", "×"］` の順である。HTML版はこの順番を維持する。
5. `block_shuffle` は `null` または `1` であり、HTML版は `1` の問題で選択肢の順番を維持する。
6. `comment_1` が `null` の問題が7問あるため、解説なしの場合の表示が必要である。
7. `question_img`、`comment_2`、`mitei` は全件 `null` である。これらは初回版で使用しないが、今後の実装に備えてデータから削除しない。
8. `question_img` と `goro_img` の文字列は画像フォルダ内のファイル名を示し、`.jpg` を付けて画像を指定する。初回版では画像を表示しない。
9. 科目データ自体には総問題数の `quantity` がない。初回版では、各テーマの `questions` の件数を合計して科目の総問題数を求める。
10. 現在はテーマの `quantity` と `questions.length` が一致しているが、同じ情報が2か所にある。表示や処理では `questions.length` を正とする。
11. `users_data.question.solved` の未回答値はJavaScriptの `null` ではなく文字列の `"null"` である。
12. `users_data` は134問分存在する。初回版では回答結果を反映するが、再読み込み後まで保存する仕組みは設けない。
